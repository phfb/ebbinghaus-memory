## 10. 事故：她主动开口的念头跑进了 Web 会话（2026-10-28 14:43）

**现象**：alive 的「想他」触发了一次主动开口，那条话（「你那条还钉在最上面呢…」）没进 QQ，
而是落在了桌面 GUI 里正在干活的那个会话。

**根因链**：

1. 我今天用**真实 dataDir** 跑了四次 qq-bot 的 apply 冒烟（为了验证设置页路由）。
   apply 里的 `saveMap()` 把内存里空着的 `sessions` 写成了 `{}`，
   **覆盖了真实的 `qq-session-map.json`**（14:23:49，3 字节）。
2. 于是 alive 的 `resolveTargetSession()`（targetSession='auto'）读不到 QQ 那一局 → 掉进第二分支：
   `state.focus.sessionId` —— 那是「他最近说话的那个会话」，也就是**桌面会话**。
3. 念头就这么投进了 Web 会话。14:42 重启后 qq-bot 内存里是空映射，14:43 他在 QQ 发图时又新建了一局，
   但那局的 id 也没落盘。

**修的三处**：

- `qq-session-map.json` 已写回第 8 局（`session-4faeb755…`，gen 8；会话目录与记忆绑定都还在）
- qq-bot `saveMap()` 加保护：**内存为空、磁盘有记录 → 拒绝写盘**，只 warn
- alive `resolveTargetSession()` **删掉「退到他最近说话的会话」这条回落** ——

**教训**：动宿主侧代码的离线冒烟，**必须用临时 dataDir**，否则冒烟本身就是一次数据事故。

**需要重启**：qq-bot 当前内存里是 14:43 新建的那一局，重启后才会读回第 8 局。

## 11. 补回漏掉的「情绪速率」整组（2026-10-28 15:0x）

他一句「最重要的数值和倍率调整窗口哪去了」把我问住了 —— 是真的漏了。

**怎么漏的**：调参表是用正则从两个 PowerShell 窗口的 `Add-Text / Add-Number / Add-Bool` 抄出来的。
alive 的「情绪速率（多久攒满）」那一组用的是 **`System.Windows.Forms.TrackBar`**（滑条），
不是那三个函数，于是整组没被扫到。

**全量比对结果**（配置键 vs 面板覆盖）：

- alive：缺 `moodFillHours` + `moodRates.{missing,jealousy,warmthGain,warmthDecay,worry,boredom,annoyanceDecay,lust}` —— **9 项全补**

**补的方式**：

- schema 加一组「情绪速率（多久攒满）」：基准小时数 + 8 条 `range` 滑条（0.1x ~ 10x，步进 0.1）
- 客户端新增 `range` 控件类型；滑条右边实时显示「N.Nx · 满值约 X 小时」（暖意·涨那颗显示「每次哄 +N%」，
  跟 PowerShell 版同一套算法：`baseline / mul`）
- 宿主读写支持**点号路径**（`moodRates.missing`）：原来直接 `next[field.path] = v` 会写成一个平铺的怪键，
  alive 根本读不到

实测：GET /panel 返回 10 组 48 项；POST 写 `moodRates.missing=2.5` 落成**数字 2.5**，
其它 7 个 rate 键原样保留、没有平铺怪键。（这次测试用的是**临时 dataDir**，不再碰真实配置。）
