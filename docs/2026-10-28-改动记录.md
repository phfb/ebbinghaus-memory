## 2. ebbinghaus-memory（记忆插件）

### 2.1 事故：QQ 记忆串到 workspace

真事：第 8 局 QQ 会话（`session-4faeb755…`）从 05:07 换局起，一整天写的记忆全落在 **workspace**，而 `bot-space.json` 锁的是 **private**；面板还一直显示「还没填分区 id」，而实际早就锁好了。

三处根因 + 一处显示 bug，全在 `src/host/index.mjs`：

| # | 问题 | 修法 |
|---|---|---|
| 1 | `session/event` 上**每个事件**都绑分区；qq-bot 换局时先 `agents.create()`，会话建立那一秒发出不带 `source` 的 header 记录 → 被钉在"当时激活的分区" | 只在 `user/message` 上建绑定 |
| 2 | 锁定分区对**已绑错**的会话没有纠错能力（`bindIfNew` 只加不改） | 桥接来源的消息进来时，绑定 ≠ 锁定分区就改回并记日志 |
| 3 | `spaceForIncoming` 把桌面端（`source.kind='user'`）也当桥接 → 桌面会话可能被专区抓走 | 新增 `isBridgedSource()`：`user` 明确排除 |
| 4 | 面板 reason 读 `config.botSpaceId`（yml 里的空值），永远是「还没填分区 id」 | 改读 `botSpaceId()`（锁定值） |

附带：`botUins` 设了号时，**不带号**的桥接消息（qq-bot 派活）也算专区 —— 否则它会先把新局钉到激活分区。

### 2.2 新功能：对话页的「分区标签」

## 5. dsh-qq-bot

### 5.1 qzone 默认号写反了（「我的说说」错认的病根）

- 原工具描述：「不给 uin 就是他自己号的空间」+「想看他最近发了什么，直接 list 就行」
- 实际：不带 `target_uin` 时 OneBot 返回的是**挂载 bot 自己那个号**的空间
- 结果：她照着描述把 bot 号的说说当成他的，反过来又说成自己的（10-28 03:47 那次纠正就是踩这个）

修法：
- `list` / `detail` / `like` / `comment` 默认目标改成**他的号**；看自己发过的要显式 `uin:"me"`
- 工具描述重写：两个号分别是谁、发说说挂在哪个号名下

### 5.2 设置页 API 从来就没注册成功过

`apply` 里 `ctx.get('webServer')` 取的时候宿主还没这个服务 → 每次启动都打「设置页 API 未注册」→ 插件页那张表单永远是空的（所以只能用 PowerShell 窗口调参）。

改成 defer 注入（`ctx.inject(['webServer'], …)`），服务起来才挂路由、卸载时注销。

### 5.3 新面板：DSH-BOT（调参）

- 侧栏 `sidebar.panellist` + `main`，id `dsh-bot-settings`，label **DSH-BOT**
- 两个标签：
  - **QQ 机器人**：直接复用插件自带那张表单（33 项 / 9 组 + 运行状态 + 读 BOT 号 + 重连 + 清空会话 + 日志），按钮已挪到字段**上面**
  - **活人感**：表驱动生成 39 项 / 9 组；顶部一块**只读状态卡**（七维情绪 + 今日开口次数 + 上次主动 + 连续被忽略 + 投递统计）
- 调参表：`lib/settings-schema.mjs`（从两个 PowerShell 窗口逐项抄成数据，以后加字段只改这一处）
- 接口：`GET /api/dsh-qq-bot/panel`（配置 + 调参表 + 只读状态）、`POST /api/dsh-qq-bot/panel`（只认表里的键，数字按 min/max/step 夹紧，数组字段逗号分隔 ↔ 数组）
- alive 的配置按 `DATA_DIR/alive-config.json` 推；读不到就整页禁用并显示路径，不猜、不自动建
