# Ebbinghaus-memory

[![CI](https://github.com/phfb/ebbinghaus-memory/actions/workflows/ci.yml/badge.svg)](https://github.com/phfb/ebbinghaus-memory/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](./LICENSE)
[![Node](https://img.shields.io/badge/node-%E2%89%A522-brightgreen.svg)](./package.json)
[![零依赖](https://img.shields.io/badge/dependencies-0-brightgreen.svg)](./package.json)

给 DeepSeek Harness 的一套**会遗忘的记忆**。

不是「把所有对话存进一个文件然后每轮都塞回上下文」。是真的按艾宾浩斯曲线跑：
刚发生的事记得清楚，七天后只剩判断过重要的那部分，二十八天后再筛一次，最后
沉成「我记得你是这样的人」。该忘的忘掉，忘了的还能按关键词翻出来。

---

## 一眼看懂

```
      一轮对话结束
           │  每 N 轮回调一次模型，精简成 1~3 条记忆（带时间戳、带权重）
           ▼
   ┌───────────────┐   7 天到期，按权重判断
   │  短期 short   │──── weight ≥ 0.55 ───▶ ┌───────────────┐
   │  「刚发生的」  │    weight < 0.20 ───▶ │  长期 long    │
   └───────────────┘    淘汰                │  「记得有这事」 │
           │                                └───────────────┘
           │  条数超上限 → 回滚压缩：最老的几条合并成一条更模糊的  │  28 天到期
           ▼                                                      ▼
                                    ┌───────────────┐
                                    │ 永久 permanent │  「我记得你」
                                    └───────────────┘
```

三条不能动的东西：

1. **每条记忆都带时间戳**，而且是**事件发生的时间**，不是入库时间。迁移进来的
   旧档案也用它原来的时间。
2. **越深越模糊，但不会模糊成没有**。压缩后的细节有 40 字下限 —— 遗忘是模糊，
   不是删除。
3. **检索是「查找」不是「载入」**。命中三条就只给三条，绝不把整个分区倒进上下文。

## 装

需要 **Node ≥ 22** 和 **DSH ≥ 0.2.0-rc.2**。没有 `npm install` 这一步 —— 零依赖、零构建。

```powershell
git clone https://github.com/phfb/ebbinghaus-memory.git
dsh plugin --profile desktop add "link:<克隆下来的目录>"

# 然后重启 DSH
```

> `link:` 是本地路径安装，克隆到哪儿都行 —— 但别放进某个 `node_modules` 里，会被下一次安装冲掉。

第一次启动会在 `$DSH_HOME/ebbinghaus-memory/` 建库（`DSH_HOME` 默认是 `~/.dsh`）：

```
meta.json
short.jsonl       一行一条，能用记事本直接打开
long.jsonl
permanent.jsonl
```

**这四个文档是首次运行就建好的**，不用手动初始化，也不会等你聊到够格才冒出来 ——
装完重启一次 DSH，去目录里看，它们已经在等着了（三个分区文件都是空的，0 字节）。
建好之后插件再不碰它们，重启不会重写、也不会重置 `created_at`。

想放到别处（同步盘、另一块盘），改设置里的 `dataDir`。
**删掉整个目录就等于忘光** —— 没别的地方留副本（除非你自己导出过）。

## 每轮往上下文里放什么

**不是全放。** 默认预算 1400 token，按这个顺序装：

| 装什么 | 默认条数 | 说明 |
|---|---|---|
| 短期全部 | 最近 12 条 | 相当于「今天和这两天发生的事」 |
| 长期随机 | 3 条 | **完全随机**抽 —— 人也会突然想起某件旧事 |
| 永久少量 | 3 条 | 人格、习惯、雷区优先 |
| 这轮检索命中的 | 最多 3 条 | 只在你提到某件「没有上下文」的事时才出现 |

装不下就按这个顺序砍：**长期 → 这轮检索命中的 → 短期里最老的 → 永久（最后）**。

永久区放最后是实测改过来的：原来它排在短期前面被砍，结果短期 10 条 ×200 字
把预算吃光，「我记得你是什么样的人」一条没进去，「上周二改了个 BOM」留下来了。
永久区只有三四条、每条一百来字，体积最小、价值最高，是底色。

## 设置项（DSH 插件设置页里全都能改）

### 周期

> **这里的「天」算的是时间戳差，不是自然日。**
> `shortDays: 7` = `now - 事件时间 ≥ 168 小时`。
> 1 号 23:00 记的事，到 8 号 00:00 只过了 6 天 1 小时，**不算到期**；
> 必须实打实过满 168 小时。你几天不上线，记忆也不会因为「跨了零点」白老一天。
> 后果也说清楚：真过了 10 天没聊，回来第一次对话会把积压的一次性处理完
> （该升的升、该忘的忘），不会丢。

| 键 | 默认 | 说明 |
|---|---|---|
| `shortDays` | 7 | 短期记忆周期（7 × 24 小时）。到期按权重大扫除 |
| `longDays` | 28 | 长期记忆周期（28 × 24 小时）。到期再筛一次 |
| `writeEveryTurns` | 2 | 每几轮对话写一次记忆。**会话第一轮必写**（不然「问一句就走」永远记不住）；1 = 每轮都写（贵，但最全） |

### 容量（超了就回滚压缩）

| 键 | 默认 | 说明 |
|---|---|---|
| `shortCapacity` | 120 | 短期最多几条 |
| `longCapacity` | 600 | 长期最多几条 |
| `permanentCapacity` | 1000 | 永久最多几条 |
| `totalTokenCapacity` | 100000 | **全库总量上限**（token，渲染口径，上限 300000） |

条数满了不丢数据，而是把**最老的几条合并成一条更模糊的记忆，压进下一层**。永久层再满，
就在永久层内部再合并一次（越合越短，但有下限）。

`totalTokenCapacity` 是第二道闸，管的是**体积**而不是条数：把库里每一条按注入格式
渲染成文字，按「中文 ≈ 1.8 字 / token」估算，合计多少。超了同样走回收 —— 挑最老、
权重最低的，一区一组压成一条，原文进 `_archive/`。两道闸谁先到谁生效。

为什么要两道：1000 条永久记忆里只要混进几篇三千字的旧档案，条数才用掉 5%，
检索和面板就已经在拖了。

> 细节和取舍见下面「容量与 token 开销」一节。

### 强度（详细度）

| 键 | 默认 | 说明 |
|---|---|---|
| `shortDetail` | 0.9 | 短期保留多少细节 |
| `longDetail` | 0.55 | 长期 |
| `permanentDetail` | 0.3 | 永久 |

调高 = 注入里每条更长（花更多 token）；调低 = 更模糊、更像「印象」。**磁盘上永远
保留完整细节**，强度只影响「现在给你看多少」。

### 载入

| 键 | 默认 | 说明 |
|---|---|---|
| `loadShortCount` | 12 | 每轮带几条短期 |
| `loadLongRandom` | 3 | 每轮随机想起几条长期（0 = 不想起） |
| `loadPermanentCount` | 3 | 每轮带几条永久 |
| `budgetTokens` | 1400 | 注入总预算硬顶 |

### 门槛

| 键 | 默认 | 说明 |
|---|---|---|
| `promoteShortToLong` | 0.55 | 到期时权重到这个数才升长期 |
| `promoteLongToPermanent` | 0.7 | 升永久 |
| `forgetBelow` | 0.2 | 低于这个数直接忘掉 |
| `recallTop` | 3 | 检索最多取回几条 |
| `recallThreshold` | 2 | 本地自动检索的命中门槛（调高 = 更少主动翻旧账） |

### 自检（重复记忆合并）

| 键 | 默认 | 说明 |
|---|---|---|
| `dedupEnabled` | true | 开不开自动自检。关掉之后面板上「立刻自检」照样能手动跑 |
| `dedupEveryEntries` | 30 | 每写入多少条记忆自检一次。**区间 5-100** |
| `dedupThreshold` | 0.5 | 重复判定阈值。0.3 激进 ~ 0.95 只合几乎一字不差的 |

详见下面「[记忆库自检](#记忆库自检重复记忆合并)」。

### 自动备份镜像

| 键 | 默认 | 说明 |
|---|---|---|
| `mirrorEnabled` | `false` | 自动备份镜像开关。**默认关**，开了也要填目录才真正生效 |
| `mirrorEveryEntries` | 5 | 每写入多少条记忆同步一次镜像。**区间 1-50** |
| `mirrorDir` | `(空)` | 镜像目录，**必须绝对路径**；留空 = 不备份 |
| `mirrorExtraPaths` | `(空)` | 额外要镜像的路径，一行一个（其它插件的数据目录之类） |

### 模型

| 键 | 默认 | 说明 |
|---|---|---|
| `provider` / `model` | 空 / 空 | 留空 = 跟随默认 provider + `deepseek-flash` |
| `reasoningEffort` | `off` | **保持 off**。固化是结构化抽取，思考只会把 token 烧在推理上、正文一个字不产出 |
| `maxTokens` | 1200 | 一次固化最多输出多少 |
| `jobTimeoutMs` | 60000 | 后台任务超时 |

## 容量与 token 开销（自己看着选）

> 这一节是给「要不要把库调大」这件事准备的。插件不替你决定，把账摆出来。

**先分清两笔账。**

| | 管什么 | 默认 | 超出时 |
|---|---|---|---|
| 条数上限 ×3 | 每个区最多几条 | 120 / 600 / 1000 | 回滚压缩：最老的几条揉成一条更模糊的 |
| 总量上限 | 整库渲染成上下文一共多少 token | 100000 | 按总量回收：最老、最不重要的那几条压掉 |
| 注入预算 | **每轮真正进上下文**多少 token | 1400 | 按顺序砍：长期 → 短期 → 永久 → 这轮检索命中的 |

**关键的一条：库大 ≠ 每轮变贵。**

每轮进上下文的只有「短期 12 条 + 长期随机 3 条 + 永久 3 条 + 这轮检索命中的几条」，
而且受 `budgetTokens` 硬顶（默认 1400）。库里有 10 万字，每轮照样只带一千多 token。
所以把容量调大，**不会**让每一次聊天都变贵。

那调大了会怎样：

- **检索变慢一点。** `memory_search` 要在更多的条目里算关键词分。几百条时无感，
  几千条时能感觉到。
- **面板渲染变慢一点。** 每区最多展示 50 条，但总量统计要遍历全库。
- **回收判断变慢一点。** 每次固化结束都会算一次总量，全库几千条时是几十毫秒级。
- **压缩更频繁。** 库越大，越容易触发「把老的揉成印象」。这是设计意图，不是故障，
  但你要知道细节会变模糊（原文在 `_archive/` 里，随时 `tools/restore.mjs` 捞回来）。

**建议怎么设：**

| 你的用法 | 总量上限 | 条数 |
|---|---|---|
| 偶尔聊两句、只想让它记住偏好 | 30K～60K | 默认够 |
| 天天用，希望半年内不清理 | 100K（默认） | 默认够 |
| 把库当日志写（`writeEveryTurns: 1`、每轮都记） | 150K～300K | 三区各再翻一倍 |

300000 是硬顶：再往上，面板统计和回收判断会开始有肉眼可见的延迟，而遗忘曲线本身
（7 天 / 28 天）也早就把细节磨没了，纯粹是在囤积。

> 当前库有多大？面板顶部那行「总量 xK / 100K token」就是。想立刻看效果，
> 面板里「调整容量 → 按总量回收一次」。

**在哪改：**

1. **侧栏面板**（推荐）：记忆面板 →「调整容量」→ 展开。改完点保存，当场生效，
   存在 `<库目录>/settings.json`，优先于 DSH 设置页。「恢复 DSH 配置」一键还原。
2. **DSH 插件设置页**：全都能改，但要重载插件才生效。
3. **`cordis.patch.yml`**：手写 `config:`，改完重启。

三处的优先级：面板覆盖值 > `cordis.patch.yml` / 设置页 > 代码默认值。

## 记忆库自检（重复记忆合并）

**问题从哪来。** 固化那一刻，模型只看得到最近十几条对话，看不到库里已经有什么。
所以同一件事会被反复记下来 —— 实测最典型的一晚，写进了三种说法的
「不在群里提他的薪资」和三条「林小满：四川人，在杭州工作」。

**为什么必须治。** 不只是白烧 token：

- 每条记忆渲染进上下文都自带「时间戳 + 标题 + 权重」的固定开销，重复三条就是三份；
- 更要命的是**检索**：`memory_search` 的 top 名额被三条同义记忆占满，
  真正有用的那条反而挤不进去。问什么没什么。

**它怎么干活。** 每写入 N 条记忆（默认 30，可调 5-100），后台做一次自检：

```text
每条记忆 → 切 2-gram（标题重复一次加权）
        → 全库 IDF 加权：稀有的词权重高，「记忆」「今天」这种满库都是的不起作用
        → 重叠系数算相似度（不是余弦：重复最常见的形态是「短的那条被长的包住」）
        → 相似度 ≥ 阈值（默认 0.5）的边，complete-linkage 聚类（挡住链式误合）
        → 跨分区合成一条，落进组内最深的那一层
```

合并后逐个字段的取舍：

| 字段 | 取谁 | 为什么 |
|---|---|---|
| `ts` | 最老的那条 | 时间戳是这件事**最早**发生的时间（和压缩同一条规矩） |
| `weight` | 最高的那条 | 同一件事被反复记下来，本身就是重要性的证据 |
| `detail` | 最长的那条 | 去重不该丢信息，只该丢重复 |
| `title` | 最短的那条（≥4 字） | 短标题信息密度最高 |
| `keywords` | 并集 |
| `depth` | 最大的 | 它已经被压过几层，这个事实要留住 |
| `zone` | 组内最深 | 一条短期 + 一条永久 → 合并后留永久 |

**三条硬保证：**

1. **不注入对话。** 这是你点名要的：它跑在后台队列里，不产生任何 systemPrompt
   片段，也不占 `budgetTokens`。你看不到它，它也不抢上下文。
2. **不调模型。** 纯本地算法，毫秒级、零成本。为省 token 去调模型是本末倒置。
3. **先冷存档再删。** 合并不可逆，原文进 `<库>/_archive/dedup.jsonl`，
   `node tools/restore.mjs --tag dedup` 能捞回来。

**阈值怎么理解。** 0.5 是拿真库调出来的：

- 0.5（默认）能合掉「林小满：四川人，在杭州工作」的三种写法、
  「雷区：不在群里提他的薪资」的两种说法、几乎一字不差的
  「我不许你说你是冰冷的代码」；
- 0.65+ 只合几乎一字不差的，漏得多但几乎不可能误合；
- 0.45− 更主动，代价是「同一天发生的两件事」也会被并成一条（细节不丢，边界糊了）。

**命令行看一眼（只演不写）：**

```powershell
cd 你的克隆目录
node tools\dedup.mjs                    # 列出会合成哪几组、省几条，不动库
node tools\dedup.mjs --threshold 0.45   # 换个阈值看看会多合哪些
node tools\dedup.mjs --apply            # 真合并（先自动冷存档）
```

> ⚠️ 跑 `--apply` 之前把 DSH 关掉，或者跑完调一次 `POST /ebbinghaus/reload` ——
> 命令行是另一个进程，插件内存里还是旧库。

## 侧栏面板

左边栏多一个「记忆」图标。点开是：

- **三根分区容量条**：短期 / 长期 / 永久，`已用 / 上限`，超过 80% 变色
- **第四根条：全库总量**：`10.4K / 100K token`，超过 80% 变警示色
- **记忆库自检**：一行状态（每再写几条触发 / 上次什么时候跑的 / 合了几组）+
  「立刻自检」按钮
- **调整容量**（默认收起，标题旁边一个「展开」）：条数上限、总量上限、注入预算、
  自检开关 / 间隔 / 阈值、周期、每轮载入条数，改完点保存当场生效；
  旁边是 token 开销说明，还有「恢复 DSH 配置」「按总量回收一次」两个按钮
- **每区可展开**：按时间倒序列出，显示「昨天 21:30 · 标题 · 权重 0.72 · 压缩 2 层」
- **检索框**：打关键词回车，只显示命中的那几条
- **按钮**：每区一个「压缩」，每条一个「忘掉」（要二次确认）
- **到期信息**：每区最近一条还有几天到期、已经过期几条

## 迁移旧记忆

仓库里**不带**针对某个私有插件旧档案格式的迁移脚本 —— 那只对原作者自己的旧数据有用。
想把别处整理好的记忆搬进来，先按下一节做一个包，再 `node tools/import.mjs --apply <包文件>` 导入：
**保留原始时间戳**，按「距今多久」自动分层，重复跑不会产生重复条目。

导完之后：插件内存里还是旧的（导入工具是另一个进程）。**重启 DSH** 就行；
不想重启也可以调一下 `POST /ebbinghaus/reload` 让它重读磁盘。

有个保护是内建的：就算你没重启，插件下次落盘前也会先把磁盘上的外部新增合并进来，
**不会把导入的几十条整份覆盖掉**。

## 多主分区（一个插件，几本互不干扰的记忆）

> **进度：三期都完了。** 目录结构 / 自动迁移 / 会话绑定 / 热切换 / 面板上的新建·改名·删除 /
> **每分区独立设置**，全都在跑。

库从「一个目录」变成了「一本一目录」：

```
<库根>\
  spaces.json              注册表：有哪些分区、当前激活哪个
  spaces\
    private\               一个分区 = 以前的一整个库（显示名「个人」）
      short.jsonl  long.jsonl  permanent.jsonl
      meta.json  settings.json  dedup-state.json  mirror-state.json
      _archive\
    工作\                  同理，完全独立
```

几个约定：

- **最多 10 个**分区；分区 id 只能是 ASCII 小写字母/数字/`-`/`_`（它同时是目录名），显示名可以中文
- **老库自动迁移**：第一次用这版启动时，发现根目录还是老结构，就整体搬进 `spaces\private\`，
  显示名「个人」。流程是**先复制 → 校验三个分区的条数 → 通过了才删原件**；
  任何一步不对就回滚，老库一个字节都不动，插件退回「直接用库根当库」的降级模式
- **镜像按分区隔离**：同步时落到 `<镜像目录>\<分区id>\`，每个分区一套清单 + 恢复程序

> 镜像也按分区隔离：自动同步时只刷「刚写过记忆的那个分区」，手动按钮刷的是**当前分区**。
> 各分区的镜像在 `<镜像目录>\<分区id>\` 下，各带自己的清单和恢复程序。

### 每个分区各管各的设置

设置页里那些旋钮（容量 / 周期 / 载入条数 / 强度 / 自检 / 镜像）是**按分区存的**：
面板上改的是「当前分区」的那份，落在 `<库根>\spaces\<分区id>\settings.json`。
切到另一个分区，看到的就是它自己的值 —— 互不影响。

**全局共用的**（不进分区设置）：`provider` / `model` / `maxTokens` / `jobTimeoutMs` /
`enabled` / `dataDir` / `debugLog`。理由：这些是「用哪张脑子、花多少 token」，换个分区不该换模型。

### 管理分区（新建 / 改名 / 删除）

面板那个下拉旁边三个按钮：

| 按钮 | 干什么 | 安全性 |
|---|---|---|
| **新建** | 输个名字，建一个空分区（目录 + 注册表） | 不动任何已有数据 |
| **改名** | 只改显示名，**id 和目录都不动** | 最安全，永远碰不到数据 |
| **删除** | **真删**：目录整个移除，删完不可恢复 | 见下面三条规矩 |

删除的三条规矩（2026-10-29 起）：

1. **Qbot 指的那个分区不许删** —— 删了 QQ 的记忆就没地方去了。按钮直接置灰。
2. **删完必须还剩一个「非 Qbot 分区」** —— 新会话仍然落到「当前记忆分区」，
   只剩 QQ 专区的话，桌面新会话的记忆会直接写进 QQ 那个库。没配 Qbot 时这条退化成「至少留一个」。
3. **挂在这个分区上的会话变成「未挂载」** —— 它们**不会**自动改写到别处，也不回落当前分区：
   注入整段不出、固化跳过、工具会提示去挑一个分区；你在对话下面那个小标签里点一下就能挂回去。

删的正好是「当前记忆分区」时，会自动切到「剩下的非 Qbot 分区里**最新创建**的那个」。

面板上的二次确认会先把影响摆出来（多少条记忆、多少会话挂在这里、删完 active 变谁、镜像备份在哪），
**并且要手打分区名**才能点「确认删除」。

镜像里那份会留着（`<mirrorDir>/<分区id>/`）当最后的救命稻草，同时会写一个 `._deleted.json`：
「从镜像恢复」见到这个标记就拒绝自动恢复，免得「删掉之后新建一个同名分区，旧记忆自己爬回来」。
真要捞：手动把那个目录里的 `*.jsonl` 拷回库目录。

## 会话没挂上分区（未挂载）怎么办

分区被删掉之后，原来挂在它上面的会话会进入「未挂载」状态 —— 这是**故意的**，不是坏了：

- 不读记忆（注入整段不出）、不写记忆（固化直接跳过）
- `memory_stats` / `memory_search` 会明说「这一局还没挂记忆分区」
- 对话输入框下面那个「脑子：XX」小标签会变成「脑子：未挂载」，点开就是一列可选的分区，
  选一个立刻恢复读写（走 `POST /ebbinghaus/spaces/bind`，属于人话，会顺手锚死）

`space-bindings.json` 里这种会话记成 `""`（空串）而不是删掉那条：
删掉就等于「从来没绑过」，下一轮会默默回落到当前分区 —— 那正是要用「未挂载」挡住的事。

### 怎么切换（热切换，不用重启）

- **面板**：侧栏顶部有一个「当前记忆分区」下拉，选一个就行
- **接口**：`POST /ebbinghaus/spaces/active { id }`

规则：**切换只影响之后新开的对话**。已经聊着的会话，在它出现的那一刻就被钉在了当时的分区，
之后你怎么切都不会动它 —— 这样「个人」里聊着的东西不会突然变成「工作」的记忆。

钉住的记录落在 `<库根>\space-bindings.json`：

```jsonc
{
  "version": 1,
  "bindings": { "session-xxxx": "work" },   // 会话 → 分区
  "locked":   { "session-xxxx": true }      // 这个落点配不配被推翻
}
```

`locked` 是「这个绑定是被一句人话钉死的」—— 钉死之后**只有他本人在面板上手动改，
或者一条真消息把它纠正到 bot 专区**能改动它；`runtime-context` / `skill-catalog` /
`time-context` 这类 harness 自己追发的系统事件永远改不动（2026-10-29 修的：
这些事件的类型也是 `user/message`，之前被误判成外接桥接，会把刚钉好的分区当场改走）。
老文件没有 `locked` 字段时一律按「没钉死」处理，好让被提前钉错的 QQ 会话仍能被
下一条真消息自动纠正。

想让某个会话改跟别的分区：`POST /ebbinghaus/spaces/bind { sessionId, id }`
（手动改属于人话，会顺手标成已钉死）；想让它重新跟随当前分区：
`POST /ebbinghaus/spaces/unbind { sessionId }`。

## 自动备份镜像（记忆 + 人格提示词 + 插件配置）

怕库坏了、怕换机器搬不走，就把整份「她的东西」同步到另一个目录 —— 那个目录里还带一个
双击就能用的恢复程序。**默认不启用**，要么在设置页打开，要么用命令行手动跑一次。

### 镜像里有什么

```
<镜像目录>\
  mirror-manifest.json   清单：源路径、条数、每个文件的大小和时间
  恢复记忆.cmd            双击这个（终端里问一句 y/N）
  _restore-memory.ps1     .cmd 的实现，别手改（下次同步会覆盖）
  library\               三分区 jsonl + meta + settings + dedup-state + _archive
  dsh\                   AGENT.md、prompt-inject.md
  extra\                 你在「额外要镜像的路径」里列的（其它插件的数据目录）
```

**不放**：`node_modules`、插件源码、exe、`__pycache__`、`*.pyc`、`*.bak-*` —— 那些重装一份更干净。

### 怎么开

1. 设置页 → 「自动备份镜像」那组：打开开关、填镜像目录（绝对路径）、按需填额外路径
2. `mirrorEveryEntries` 决定多勤：默认每写入 5 条记忆同步一次
3. 想立刻验证一次：

```bash
node tools/mirror.mjs --dir D:/mirror/ebbinghaus          # 只看清单
node tools/mirror.mjs --dir D:/mirror/ebbinghaus --apply   # 真写
```

### 怎么恢复

打开镜像目录，**双击 `恢复记忆.cmd`**。它会：

1. 读清单，把备份时间、条数、原始库目录打印出来
2. 自己找这台机器上的记忆库位置（清单里的路径 → `$DSH_HOME` → `~/.dsh` → DSH profile 里的 junction，一路找）
3. 问一句「确认执行记忆恢复? (y/N)」
4. **先把当前库整份备份**到 `<库目录>\_backup-before-restore-<时间戳>\`
5. 按清单写回 `library\` / `dsh\` / `extra\`

换机器、库换位置、或者只想恢复到别处：命令行加 `-Target <目录>`。

> ⚠️ 两个注意：
> - 镜像目录**不能和记忆库目录互相嵌套**（会自己复制自己），插件会直接拒绝并说明原因
> - 如果额外路径里放了带 token 的配置（比如 `profiles\desktop\cordis.patch.yml`），**镜像目录别放网盘或公开位置** —— 那是明文凭据

## 导出 / 导入（跨端同步）

> AstrBot 版（`D:\Ebbinghaus-memory-ForAstrbot`）读写**同一个记忆库目录**，
> 两端的包格式完全一致，随便哪边导出、哪边都能导。

```powershell
# 导出（默认写到 <库>/_exports/）
node tools/export.mjs

# 看会变成什么样（不写盘）
node tools/import.mjs 你的包文件路径

# 真导入（自动备份到 <库>/_backup-<时间戳>/）
node tools/import.mjs --apply 你的包文件路径
```

> 这台机器 PATH 里没有 `node`，用 DSH 自带的：
> `$env:ELECTRON_RUN_AS_NODE='1'; & '你的DSH安装目录\DSH NEXT.exe' tools\export.mjs`

**合并规则**：按 id 合并，不覆盖。同一个 id 两边都有时，`weight` 高的赢；
weight 相同看谁 `depth` 小（更原始）；还相同取 `ts` 早的。`zone` 取更深的那个。
**本地删过的 id 会被墓碑挡住，不会被导回来。**

## 冷存档：压缩掉了，但原文还在

压缩是**不可逆**的 —— N 条原始记忆揉成 1 条模糊的，那 N 条就从库里消失了。
这是整个系统里唯一会真丢东西的地方，所以它先写一份原文进 `_archive/`：

```
<库>/_archive/compressed.jsonl    被压缩合并掉的原文
<库>/_archive/dropped.jsonl       到期被淘汰的原文
```

**这两个文件不进注入、不占容量、不参与检索**，只在你主动翻的时候才出现。
要捞回来：

```powershell
# 看有哪些归档
node tools/restore.mjs --list

# 看看能恢复什么（默认只演不写）
node tools/restore.mjs --tag dropped
node tools/restore.mjs --since 2026-10-20
node tools/restore.mjs --keyword 桌宠
node tools/restore.mjs --id em-20261022T0448-a1b2

# 写回去
node tools/restore.mjs --tag dropped --apply
```

恢复的条目会带着它**原来的分区**回去，墓碑一并撤掉。归档文件不动，可以重复捞。

## 两只工具（`memory_search` / `memory_stats`）

给模型用的两只手，**都跟着「这一局绑定的分区」走**（2026-10-29 起）：

- `memory_search { query, top? }` —— 跨区关键词查找。输出会带分区：
  `找到 2 条（分区：工作（work））：…`
- `memory_stats` —— 三区容量 + 合计 + 上次固化 + 分区，共 6 行，最后一行永远写着
  `分区：工作（work）`，让你一眼看出读的是哪个库。

几条规矩：

- **跟着会话**：会话钉在哪个分区就只查那个分区。以前它读的是「当前激活分区」，
  于是「面板写着 A、这局钉在 B」时，模型问容量拿回来的是 A 的数 —— 看着就像串了。
- **子代理 / fork 会话**：自己不绑分区、也不写记忆，读的时候**继承派它的那一局**的分区
  （沿 `session.header.parentSession` 往上找最近一个有绑定的祖先），输出会标
  `（继承派它的那一局）`。
- **未挂载的会话**：什么都不读，直接说「这一局还没挂记忆分区，去小标签里选一个」。
- **工具不落绑定**：拿不到会话、或整条链都没绑定时才跟随当前分区，而且不会因为这个把分区钉下来 ——
  钉分区只由第一句人话决定。

## Qbot 记忆专区与 BOT 分区锁

装了 `dsh-qq-bot` 之后，可以给 QQ 那边单独指定一个分区（面板「bot 记忆专区」里选，
选定后钉死不可改）。规则：**QQ 来的会话一律读写那个分区**，跟「当前记忆分区」怎么切、
开多少新会话都无关。

上面还有一个开关 **BOT 分区锁**（**默认打开**）：

> 打开后其他对话无法对它读写。

打开时：

- 桌面**新会话不会落进**这个分区（哪怕「当前记忆分区」正指着它 —— 会改落到
  「非 bot 分区里最新创建的那个」）
- 手动把会话挂进去会被拒（`400`）
- **已经**挂在这个分区里的非 QQ 会话会立刻变成「未挂载」
- QQ 会话不受影响（靠「这个会话发来过 QQ 人话」认出来，记在 `bot-space.json` 的 `sessions`）
- 「当前记忆分区」**仍然可以切到这个分区**（用来进去看），下拉里会标「锁定中（仅查看）」
- 面板的管理入口（浏览 / 忘记 / 导出 / 体检 / 从镜像恢复）不受限制 —— 锁只管对话

⚠️ 锁生效需要三个条件同时成立：**装了 qq-bot + 选了专区 + 那个分区还存在**。
缺任何一条就不生效、不报错 —— 全新部署、没装 bot、装了还没选区，都不会被它影响。

开关存在 `<库根>/bot-space.json` 的 `lockForeign`（老文件没有这个字段时按「打开」算），
接口是 `POST /ebbinghaus/bot-lock { locked: true|false }`。

## 排错

**记忆不增长？**

1. 每 `writeEveryTurns` 轮才写一次 —— 先多聊两轮。
2. 后台固化是结构化抽取，模型返回不合法 JSON 时**整批丢弃**（宁可不记，也不写坏档）。
3. 打开设置里的 `debugLog`，日志里应该按顺序出现：
   `记忆库就绪` → `已注册注入段` → `开闸` → `固化开始` → `模型返回` → `记下 N 条`。
   哪一行断了，问题就在那一行之后。

**注入里没有记忆？**

新库前几轮是空的，正常。看面板容量条有没有东西 —— 有东西但注入没有，就是
预算裁掉了（调大 `budgetTokens` 或调小 `loadShortCount`）。

**面板打不开？**

面板数据走 HTTP：`GET /ebbinghaus/state`。在浏览器控制台里看这条请求的返回，
有 `{ok:false, error}` 就直接说人话告诉我是哪句。

**面板点「忘掉 / 收割 / 压缩 / 自检 / 回收 / 导出 / 重读」提示「正在固化记忆，稍等几秒再试」？**

这是故意的（`409`）。固化要等模型，那几十秒里「当前在操作哪个分区」是钉在那个会话上的；
这时候让面板的写操作跑下去，会作用到**别的分区**。等它跑完再点一次就行。
读类（打开面板、看容量）不受影响，永远显示「当前记忆分区」的真实数据。
